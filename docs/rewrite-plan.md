# XuPurse 重写计划（Flutter）

> 状态：🚧 规划中（2026-09-17 制定）
>
> 本文件是 XuPurse 从 0 用 Flutter 重写 cent-xyx 的**总路线图**。目标：三端（Web / Android / iOS）一致、历史包袱最小、第三方导入与数据库表零偏差。

## 1. 范围决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 技术栈 | Flutter（Riverpod + drift + fl_chart + intl） |
| 金额单位 | **万分之元整数**（1 元 = 10000），与三方「元」无损换算，继承 cent-xyx 已验证逻辑 |
| 附加功能 | ✅ 保留：局域网同步、AI 助手/语音记账 |
| 附加功能 | ❌ v1 不规划：地图可视化、周期记账（Cent 1.1 引入，非个人定制） |
| 一木特色业务 | ✅ **完整支持**：转账（含手续费/到账额）、借贷、退款、报销、分期（独立表 + UI + 逻辑闭环） |
| 多币种 | ✅ **完整支持**：账户独立币种、内置汇率表、手动覆盖、总资产折算 |
| 数据模型基准 | 以**一木记账**为业务蓝本（用户目标），兼顾昼虎 / 钱迹字段 |
| 旧数据 | 不需要迁移 cent-xyx 旧数据（从 0 开始） |

## 2. 设计原则（避免重蹈覆辙）

> 核心目标：**不再造屎山**。以下原则从 cent-xyx 的踩坑中提炼，每一条都是硬约束。

1. **数据库是唯一事实来源**，状态层（Riverpod）只做只读缓存，绝无「localStorage + meta 双写」。
2. **金额统一万分之元整数**，仅 UI 层转换；任何 Service / Repository 入参出参约定一致，从根上杜绝数量级 bug。
3. **「账单 + 账户余额 + 快照」必须处于同一事务**，要么全成要么全回滚。
4. **快照 `billId` 先定后写**：先确定落库 ID，再写快照，保证失效逻辑可用。
5. **数据库结构变更一律走 migration**，禁止删库重建。
6. **批量操作单次事务**，禁止逐条串行 `await`（大数据量假死的根源）。
7. **导入幂等**：持久化 ID 映射 + diff，重复导入不产生重复数据；导入账单打来源标记，重算/校验时跳过。
8. **以用户输入的账户余额为权威**，允许账单与余额有差异（借鉴钱迹/随手记/Moze）。

## 3. 参考成熟记账软件设计

| 来源 | 借鉴点 | 落地位置 |
|------|--------|---------|
| 一木记账（业务蓝本） | 账户大类（资金/记录/债务）、余额流水（assethistory → 快照）、借贷/报销/退款/分期业务模型、导入 ID 映射 | 数据模型、特色业务模块、导入模块 |
| 钱迹 | 手动调账生成余额调整流水、预算执行、统计维度（收支比/储蓄率） | 账户调账、预算、统计 |
| 随手记 / Moze | 以用户输入余额为权威，不强制与账单一致；定期对账 | 余额权威值设计 |

## 4. 分阶段路线图

> 每阶段都有明确的「验收标准」，完成即标记可发布增量。依赖关系：0 → 1 → 2/3 → 4 → 5（可并行 4/5 中后段）→ 6 → 7 → 8。

### Phase 0 — 工程与数据层（地基）

**目标**：三端工程跑通，全部数据表 + 迁移机制落地，Repository 可 CRUD。

任务：
- [x] `flutter create` 三端工程（android / ios / web），配置 lint / format / pre-commit
- [x] 建立分层骨架：`core / data / domain / state / ui / l10n`
- [x] 接入 Riverpod、drift、intl、fl_chart、uuid、archive
- [x] 定义全部数据表（见 [data-model.md](./data-model.md)）+ MigrationStrategy
- [x] 账本工厂：每账本一个库（`book-<id>`），全局库存 `books`
- [x] Repository 基础 CRUD + 金额转换工具 + 领域异常体系
- [x] 单元测试：金额转换、表 DDL、账本创建/切换

**验收**：`flutter analyze` 0 error；表结构单测通过；切账本数据隔离正确。

### Phase 1 — 核心记账闭环

**目标**：能完成「记账 → 转账 → 调账 → 看趋势」的完整闭环。

任务：
- [x] 首页账单列表（分页 / 懒加载）
- [x] 记账弹窗：支出 / 收入 / 转账 + 金额键盘 + 二级分类 + 账户选择 + 默认账户
- [x] 余额联动与快照自动创建（[算法一](./algorithms.md)）
- [ ] 账户管理：三类账户 CRUD、调账（[算法二](./algorithms.md)）、历史快照、账户合并、删除
- [x] 总资产 + 资产趋势图（[算法四/五](./algorithms.md)）
- [ ] 单测 + 关键路径 widget 测试

**验收**：记账/删除/修改后余额、快照、趋势三者一致；调账后不被重算覆盖。

### Phase 2 — 辅助数据与多币种

任务：
- [x] 分类管理（两级、自定义、调账专用分类）
- [ ] 标签管理（分组、preferCurrency）
- [x] 预算管理（卡片 + 表单 + 进度）
- [ ] 多币种：本位币、内置汇率表、手动覆盖、账户币种、外币账单当时汇率

**验收**：汇率换算公式单测（`convert = amount × rate[to] / rate[from]`）；外币总资产折算正确。

### Phase 3 — 统计与搜索

任务：
- [ ] 统计页：收支对比、分类占比、预算执行、趋势
- [x] 搜索：多条件筛选 + 模糊搜索 + 范围限定（全部/备注/标签/金额）
- [ ] 搜索结果分析页（趋势 + 占比 + 词云）
- [ ] 大数据量（10 万+ 账单）性能：分页、索引、isolate 统计

**验收**：10 万账单下搜索/统计流畅；筛选结果与手工核对一致。

### Phase 4 — 特色业务（借贷/报销/退款/分期 + 完整转账）

任务：
- [x] 转账完整：手续费、到账金额、跨币种转账
- [ ] 借贷管理 UI：借出 / 收回、利息、还款账户
- [ ] 报销管理 UI：报销、结束、关联账单
- [ ] 退款管理 UI
- [ ] 分期管理 UI（期数、服务费、账期）
- [ ] 各业务与账单 / 账户余额 / 快照联动

**验收**：每类业务新建/修改/删除后，关联账单、账户余额、快照全部一致。

### Phase 5 — 第三方导入（核心卖点，最高保真）

**目标**：一木 / 昼虎 / 钱迹 `.db` 导入零丢失、重复导入幂等。

任务：
- [x] 通用导入框架：`parse → map → diff → preview → write → mapping`
- [x] **一木** 解析 + 映射 + diff（accountbook/asset/category/bill/transfer/lend/budget/assethistory/refund/reimbursement/instalment）
- [x] **昼虎** 解析 + 映射 + diff（account_book/account/category/bill/account_change_log/budget）
- [x] **钱迹** 解析 + 映射 + diff（account_book/account/category/bill，含 extra 报销/退款/多币种）
- [x] 同名账户合并检测（[算法八](./algorithms.md)）
- [ ] 预览弹窗 + 覆盖/增量模式
- [x] Web 端 WASM 加载 SQLite；原生端直接读 .db

**验收**：
- 用三家真实备份文件导入，**字段级对比无丢失**（账单数、金额、分类、标签、快照、业务实体全对齐）
- 同一文件导入两次不产生重复数据
- 导入后余额以第三方权威值为准，重算不翻倍

## 6. 风险管理

| 风险 | 缓解 |
|------|------|
| 三方 DB 结构随版本变化 | 解析层做容错（字段缺失给默认值）；预留 Schema 版本探测 |
| Web 端 WASM 加载兼容性 | 显式 locateFile；部署校验 MIME |
| 大数据量性能 | 从 Phase 0 就建立分页与索引规范；统计走 isolate |
| 导入数据量大（10万+） | 批量单事务写入 + 进度展示 + 后台 isolate |
| 借贷/报销等业务逻辑复杂 | 每业务独立 Service + 单测，先于 UI 完成逻辑闭环 |
