## 金额与数据

### Q1. 金额为什么会差 10000 倍 / 数量级错乱？

**原因**：金额内部用整数「万分之元」（1 元 = 10000）存储，UI 显示与存储必须成对转换，混用会差 4 个数量级。

**解决**：
- 显示：`amount / 10000`（保留两位小数）
- 存储/入参：`amount * 10000`
- 所有 Service / Repository 接口入参出参统一万分之元，仅 UI 层转换

### Q2. 总资产 / 趋势图与账户余额对不上？

**原因**：上一代曾出现两类问题：
1. 手动调账后仍按账单反推余额（否定用户矫正）；
2. 快照 `billId` 与实际账单 ID 不一致，导致快照失效逻辑失效。

**解决**（设计红线）：
- `currentBalance` 是权威值，总资产直接使用，不反推。
- 快照的 `billId` 必须与最终写入的账单 ID 完全一致（**先确定 ID 再写库**）。
- 删除/修改账单时，关联快照要标记 `isValid=false`。

### Q3. 删除/修改账单后，趋势图出现"幽灵数据"？

**原因**：删除账本未清理 `balanceSnapshots`，或账单删除未失效快照。

**解决**：
- 删除账本级联删除账户与快照。
- 账单增删改统一走 Service，由 Service 负责快照失效，禁止绕过。

### Q4. 为什么"重新计算余额"会覆盖我的手动矫正？

**设计使然**：`recalculateAllBalances()` 将账户重置为 `initialBalance` 后按非调账账单重算，**会覆盖所有手动调整**。

**建议**：
- 仅在刚导入大量历史数据、数据异常时使用。
- 每月初对账后不要点「重新计算」，直接编辑账户余额（走调账）。

## 第三方导入

### Q5. 一木导入后执行"重新计算余额"导致余额翻倍？

**原因**：导入时 `initialBalance` 被设为一木权威值（`currentBalance`），历史账单又参与重算，导致重复累加。

**解决**：
- 导入的账单标记 `extra.isYimu = true`（同理 `isZhouhu` / `isQianji`）。
- `recalculateAllBalances` 与 `validateAccountBalances` 必须**跳过**标记了导入来源的账单。
- 一木导入后 `currentBalance` 以 `asset.assetnumber` 为权威值，不要再重算。

### Q6. Web 端导入 .db 报 "wasm magic word" 错误？

**原因**：sql.js 的 WASM 文件未被正确加载——dev server 或静态托管把 `.wasm` 请求返回成了 HTML。

**解决**：
- 必须显式配置 `locateFile` 指向真实的 `.wasm` 路径。
- 部署时确认服务器返回 `application/wasm` MIME 类型。

### Q7. 同一文件重复导入产生重复账单？

**原因**：缺少幂等机制。

**解决**：
- 维护持久化 ID 映射（`yimuMapping` / `zhouhuMapping` / `qianjiMapping`）。
- 导入前做 diff：已存在的业务 ID 跳过或更新，不重复创建。
- 覆盖模式（overlap）会清空重写，仅首次或明确需要时使用。

### Q8. 导入后账户/分类/标签没生效？

**原因**：导入时 meta 写入不完整，或账户只写入了 store 未写入 meta。

**解决**：
- 导入时**一次性写入完整 GlobalMeta**（账户、分类、标签、预算、快照、映射）。
- 任何账户/快照修改后同步写回 meta（单一事实来源）。

## 存储与性能

### Q9. 数据量大时页面卡死 / 假死？

**原因**：上一代出现两类问题：
1. 批量导入逐条 `await` 串行写库；
2. 列表筛选"全量加载再过滤"。

**解决**：
- 批量操作必须聚合后单次写库（一次事务）。
- 列表按需加载（首屏 N 条），滚动到底再加载；统计/搜索走隔离层（Worker / isolate）。
- 趋势计算避免 O(n²)，用快照 + 二分查找（见算法文档）。

### Q10. 快照数据会不会撑爆存储？

**原因**：上一代曾将快照存 localStorage（5-10MB 上限），长期记账会崩溃。

**解决**：
- 快照入账本数据库（drift / SQLite），不占用 localStorage。
- 趋势图只读 `isValid != false` 的快照。

### Q11. 切换账本后账户数据错乱（出现别的账本的账户）？

**原因**：账户缺失 `bookId` 或查询未按账本过滤。

**解决**：
- 查询账户必须兼容 `bookId` 为空（旧数据）与等于当前账本的情况：
  `!a.bookId || a.bookId == currentBookId`。
- 新建账户必须写入 `bookId`。

## 界面与体验

### Q12. 图标不显示 / 控制台报 "icon not found"？

**原因**：上一代用 iconify `icon-[mdi--xxx]` 语法，写错图标名会静默失败。

**解决**：重写后统一使用 Flutter 图标方案（flutter_iconify / 自绘 SVG），并建立图标清单避免拼错。

### Q13. 账单金额显示为 0？

**原因**：`amount` 为 0 或未做 `/10000` 转换。

**解决**：检查数据来源（是否经过 Service 归一化）与展示转换。

### Q14. 深色模式下图表看不清？

**解决**：图表颜色需随主题切换，从主题色板取值，不要硬编码浅色背景。

## 环境与构建

### Q15. `flutter analyze` 报大量 warning？

**建议**：
- 以 0 error 为门槛，warning 尽量清零。
- 禁止用 `// ignore` 大面积压制告警（上一代遗留了大量 biome-ignore，重写时不带入）。

### Q16. Web 端本地存储与原生端数据不互通？

**说明**：Web（IndexedDB）与移动端（SQLite）物理存储不同，数据互通依赖「导出备份 JSON → 导入」机制。

### Q17. 提交时 lint / format 自动失败？

**解决**：启用 pre-commit hook（`husky` 或 Flutter 侧 `dart format --fix`），提交前先 `dart format` + `flutter analyze`。
