# XuPurse UI 大排查改造计划(横竖屏适配 / 刷新与释放 / UI一致性 / 页面基类 / 主题定制系统)

> **For Hermes:** 按阶段推进,每阶段完成后跑 `flutter analyze`(0 警告红线)+ `flutter test` + chrome 实跑。宽窄屏用固定 profile 验证:`flutter run -d chrome --web-port 8765 --web-browser-flag="--user-data-dir=G:\Code\env\flutter_chrome_profile_xupurse"`(PATH 用 G:\Code\env\flutter39)。

**Goal:** 让 XuPurse 在手机竖屏/手机横屏/桌面宽屏三形态下都有良好布局,数据刷新及时无泄漏,UI 设计语言统一,并建立「页面基类 + mixin + 设计 token + 可定制主题」基建,使未来主题(主色/卡片样式/字体/动画)单点可改。

**Architecture:** 四层递进 —— ①设计 token 层(常量集中) → ②主题模型扩展(AppTheme 变 ThemeConfig,buildAppTheme 全面接 token,暗色模式=独立预设主题) → ③通用组件沉淀(EmptyState/卡片壳/底部弹窗壳/SnackBar/金额色) → ④页面基类与 mixin(响应式包装、加载态渲染、dispose 登记) → ⑤存量页面**一次性全迁移**(已决策)。消费端先收口、主题层后扩展,否则主题改了也覆盖不到散落硬编码。

**Tech Stack:** Flutter 3.44 / Material 3 / Riverpod / drift watch / SharedPreferences(主题持久化,需 versioning)。

## 2. 主题模型扩展(lib/state/theme_provider.dart + lib/ui/theme.dart)

class ThemeConfig {

  final Color seedColor, background, cardColor; // 现有三色
  // 新维度(可空=跟随派生):

## 4. 页面基类与 Mixin(lib/ui/layout/)

Flutter 不适合重继承,用 **mixin 组合**(UserFacing 要求"该 mixin 的 mixin"):

```dart

  // 统一 Scaffold + AppBar + ContentWidthBox(maxWidth 可覆写)
  // 子类只实现 body/appBar/maxWidth,宽窄屏自动适配
}

// xp_async_view_mixin.dart —— 加载/错误/空态统一渲染
mixin XpAsyncView<T extends StatefulWidget> on State<T> {
  // Widget when(AsyncValue, {required Widget Function(List) data, ...})
  // 统一 loading:XpLoading 骨架/转圈(接 motion 配置)
  // 统一 error:重试按钮;统一 empty:XpEmptyState
}

// xp_disposal_mixin.dart —— 资源释放登记
mixin XpDisposal<T extends StatefulWidget> on State<T> {
  // register(controller/timer/subscription) → dispose 自动逐个释放
  // 防 TextEditing/Animation/Timer 泄漏的兜底
}
```

- 不强改 MainShell(IndexedStack 保状态是对的);statistics_page 的内部断点壳保留。
- 迁移原则:**先新页面用基类,存量页面随触碰逐步迁移**,不搞一次性全量重写(风险控制)。

## 9. 风险与开放问题

- **回归面大**:38 处卡片、37 处 SnackBar、20+ 裸 TextStyle,逐页替换需 chrome 双形态抽查,警惕视觉回归。
- **ThemeConfig 向后兼容**:旧 JSON 必须无损读取(用户已建主题)。
- **mixin 组合过度设计风险**:三件套只包"壳与状态渲染",业务逻辑绝不进 mixin。
- **性能**:fontScale 全局 textTheme 重建成本可忽略;动画默认开,低端机可关。
- **已决策(2026-09-19 用户确认)**:
  1. **暗色模式 = 独立预设主题**:系统暗色开关直接等于切换到「暗色」预设主题,与用户自定义主题完全解耦(自定义主题只在浅色模式生效,不参与暗色)。实现:themeMode 监听系统暗色 → currentThemeProvider 返回暗色预设(其配置即暗色 ThemeConfig),不再把用户 background/cardColor 塞进 dark buildAppTheme。
  2. **字体定制只做系统字体**:提供系统可选字体列表(各平台默认/常见字体)+ 字号缩放;不做自定义字体文件导入。
  3. **存量页面一次性全迁移**:开发阶段干脆全做——全部页面迁到 XpPageScaffold/XpAsyncView/XpDisposal mixin 体系,统一替换 XpCard/showXpSheet/xp_snack/限宽弹窗;按页面逐个提交粒度推进,每批迁移完跑 analyze+test+chrome 双形态抽查。
